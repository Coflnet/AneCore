# Seed data attribution

The curated `apple-iphones.json` file (23 iPhone entries, `source: seed:curated-2026-09`) is
hand-authored from Apple's published technical specifications and carries no third-party
licence obligation beyond normal fact use.

Every other file in this directory was generated by `tools/catalog-import/build_seed.py` from
the open datasets below. Retrieval date for all sources: **2026-09-28**.

## 1. GetTechAPI/TechAPI

- Source: https://github.com/GetTechAPI/TechAPI (branch `develop`)
- Licence: **CC-BY-SA 4.0** (per the repository's `LICENSE` file)
- Used for: `samsung-galaxy.json` (Galaxy S/Z Fold/Z Flip/Note **and, since the 2026-09 recall
  pass, the Galaxy A-series**), `google-pixel.json`, `xiaomi.json` (smartphone specs, grouped
  from region/carrier/storage variant records; only `verified: true` records were used). The
  A-series needed its own wanted-regex (see `build_seed.py`'s `build_samsung_galaxy_a` for why -
  TechAPI's raw A-series names include regional/carrier "Top Edition" and similar noise the S/Z/
  Note line doesn't have) rather than reusing `build_samsung`'s pattern.
- **Attribution required**: "Smartphone specification data from the TechAPI project
  (https://github.com/GetTechAPI/TechAPI), licensed CC-BY-SA 4.0."
- **Share-alike**: CC-BY-SA 4.0 is a share-alike licence. Any redistribution of this derived
  data (the `samsung-galaxy.json` / `google-pixel.json` / `xiaomi.json` files, or a database
  built substantially from them) outside AneCore itself must be offered under CC-BY-SA 4.0 or a
  compatible licence, with the same attribution notice. The AneCore product entries retain
  `Source: seed:techapi-2026-09` for traceability back to this obligation.
- TechAPI's `laptop`/`tablet`/`monitor` categories were checked but **not used mechanically**:
  spot-checked `verified: true` coverage was 6/459 Lenovo laptop files, 1/218 Apple tablet
  files, 40/589 Samsung tablet files, 33/130 Apple Watch files, 0/882 monitor files - too thin
  to group reliably under the "only verified: true" rule. See README "Coverage gaps" below.

## 2. docyx/pc-part-dataset

- Source: https://github.com/docyx/pc-part-dataset (`data/json/*.json`, fetched directly over
  HTTPS from `raw.githubusercontent.com`, no clone needed)
- Licence: **MIT**
- Used for: `gpu.json`, `cpu.json`, `monitors.json`, `ram.json`, `motherboards.json`,
  `storage.json`, `headphones.json`
- **Attribution required**: MIT only requires the licence/copyright notice to accompany
  substantial uses of the software/data; no share-alike obligation. Recommended notice: "PC
  component specification data derived from docyx/pc-part-dataset
  (https://github.com/docyx/pc-part-dataset), MIT License."
- Individual board-partner/kit SKU rows (e.g. "MSI GeForce RTX 3060 Ventus 2X 12G") were grouped
  down to the underlying chipset/model line (e.g. "RTX 3060") for GPUs/CPUs, since that is what
  resale listings actually name; monitors/RAM/motherboards/storage/headphones keep the
  individual product name docyx lists, restricted to well-known series (see "Coverage gaps").

## 3. pbakondy/ios-device-list

- Source: https://github.com/pbakondy/ios-device-list
- Licence: **MIT**
- Used for: colour/size/storage data in `apple-ipad.json` and `apple-watch.json`, and the full
  `apple-airpods.json` entries. The existing curated `apple-iphones.json` (storage options for
  iPhone 11-16) was kept authoritative and NOT overwritten by this source, per the task brief;
  it was only used to double check colour coverage exists through the generations it lists.
- **Attribution required**: MIT notice - "Apple device colour/size/model data derived from
  pbakondy/ios-device-list (https://github.com/pbakondy/ios-device-list), MIT License."
- Coverage ends around 2023 (through Apple Watch Series 8 / iPad 10th generation); newer
  generations (Watch Series 9/10/Ultra 2, iPad Pro M4, MacBook M3/M4, ...) are hand-authored
  against Apple's own published tech specs with colour left an open/free value (empty
  `possibleAttributes.color` set) rather than guessed - see README "Apple laptop/tablet/watch"
  section for why this category is hand-curated rather than pipeline-derived.

## 4. Google Play supported devices CSV

- Source: https://storage.googleapis.com/play_public/supported_devices.csv (Google, public;
  no explicit licence file - it is Google's own published compatibility list, used here only as
  a factual model-code↔marketing-name lookup, not redistributed as a dataset)
- Fetched and converted from UTF-16 to UTF-8 by `fetch.sh`, kept in the researcher's raw/
  scratch dir only. **Not currently used** in a generated seed file this pass (the TechAPI
  smartphone records already carry `SM-xxxx`-style model codes per variant, which turned out to
  be sufficient for the samsung/google/xiaomi aliases produced here) - kept fetched for a future
  pass that wants marketing-name aliases for brands TechAPI's `verified` coverage is thin for.

## 5. leavestylecode/CameraDatabase

- Source: https://github.com/leavestylecode/CameraDatabase (`data/camera_data.csv`)
- Licence: **MIT**
- Used for: `cameras.json` (Canon EOS, Sony Alpha, Nikon Z mirrorless/DSLR bodies, 2015+)
- **Attribution required**: MIT notice - "Camera specification data derived from
  leavestylecode/CameraDatabase (https://github.com/leavestylecode/CameraDatabase), MIT
  License."

## 6. Wikidata

- Source: https://query.wikidata.org/sparql, class "video game console model" (Q56682555) - see
  `tools/catalog-import/README.md` "Consoles" section for the exact query used and why its
  results were too sparse/inconsistent (128 raw results, most unrelated/unnamed prototypes; the
  mainstream PS5/Xbox Series/Switch models are not consistently typed as direct instances of
  that class) to drive `game-consoles.json` mechanically.
- Licence: **CC0** (Wikidata's own data licence) - no attribution legally required, though
  Wikidata asks it be credited as a courtesy: "Console model list checked against Wikidata
  (https://www.wikidata.org), CC0."
- `game-consoles.json`'s 22 entries (PS3/PS4/PS4 Slim/PS4 Pro/PS5/PS5 Digital/PS5 Slim/PS5 Pro,
  Xbox 360/360 S/360 E/One/One S/One X/Series S/Series X, Switch/Lite/OLED/2, Steam Deck
  LCD/OLED) are hand-curated against public manufacturer specifications and cross-checked
  against Wikidata's individual console pages, per the task's explicit allowance to hand-verify
  this category rather than force an inadequate mechanical pipeline.

## Summary of obligations for the product owner

| Source | Licence | Obligation |
| --- | --- | --- |
| TechAPI | CC-BY-SA 4.0 | Attribution **and share-alike** if the derived phone seed files (or a database built from them) are redistributed outside this product |
| docyx/pc-part-dataset | MIT | Attribution notice only |
| pbakondy/ios-device-list | MIT | Attribution notice only |
| leavestylecode/CameraDatabase | MIT | Attribution notice only |
| Wikidata | CC0 | None legally required; courtesy credit given above |
| Google Play devices CSV | Google, public, unused in generated output | None (not redistributed) |

A single combined attribution notice (covering all of the above) should be included wherever
AneCore/AneApi/Ane-nuxt publish "data sources" or "credits" information, e.g. an About/Impressum
page. The TechAPI share-alike clause is the one obligation that needs active tracking: if the
`samsung-galaxy.json`/`google-pixel.json`/`xiaomi.json` seed files are ever exported/republished
as a standalone dataset (not just used internally to power matching), that export must itself be
licensed CC-BY-SA 4.0.
